# 博客文章发布最小规范

## 适用范围

本规范仅覆盖 `../source/_posts` 下正式博文的最小发布要求。
目标是保证文章能被 Hexo 正确识别、解析和生成，不额外引入内容运营层面的强规则。

## 规范来源

- `../scaffolds/post.md` 规定了新文章的最小字段集合：`title`、`date`、`tags`
- `../_config.yml` 配置了 Hexo 的日期格式和 `tags` 页面能力
- 主题 `../themes/3-hexo` 会消费文章标签用于侧边栏和筛选展示

## 最小发布要求

### 1. 文件位置

正式博文必须存放在 `../source/_posts` 下。

### 2. Front matter

文章开头必须包含 YAML front matter，且以 `---` 包裹。

标准最小模板如下：

```yaml
---
title: 文章标题
date: 2026-09-02 10:00:00
tags:
---
```

### 3. 必填字段

- `title`
- `date`
- `tags`

其中：

- `title` 必须存在
- `date` 必须存在且可解析
- `tags` 字段必须存在，允许暂时为空

### 4. date 格式

`date` 只接受以下两种格式：

- `YYYY-MM-DD`
- `YYYY-MM-DD HH:mm:ss`

不接受夹杂非日期文本、中文说明或其他不可解析内容。

## 当前不拦截的历史遗留项

以下问题当前不作为硬性违规处理：

- `tags` 为空
- 标题命名风格不统一
- 按年月目录存放与按主题目录存放并存

这些问题可以后续单独治理，但不影响文章被识别为正式博文。

## 推荐检查方式

执行以下命令扫描 `../source/_posts`：

```bash
npm run scan:posts
```

扫描结果会输出：

- 文章总数
- 合规文章数
- 缺少 front matter 的文件
- 缺少必填字段的文件
- `date` 非法的文件

## 处理原则

- 本规范优先保证“可发布”
- 不做与当前仓库历史内容相冲突的大范围重构
- 后续若要提升质量，再单独追加标签、分类、命名等运营规范
